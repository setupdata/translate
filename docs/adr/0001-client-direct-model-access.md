# ADR-0001：客户端使用用户密钥直连模型服务

状态：已接受
日期：2026-08-12

## 背景

如意翻译第一版面向个人用户，需要支持 DeepSeek 官方渠道和用户自定义的 Chat Completions 或 Responses 地址。项目当前不建设账号、计费、中转服务器或密钥托管服务，也不能在插件包中放置共享开发者密钥。

模型请求会携带源文，以及本次命中的术语、用户选择的参考译例、行业配置和附加翻译要求。精译模式会把这些资料分阶段发送给同一服务。API Key 和发送内容都属于需要明确保护的数据。

uTools 允许 `preload` 使用 Node.js 能力发起跨域请求，但要求相关源码保持可读。客户端程序因此无法把长期密钥变成服务端秘密。`dbCryptoStorage` 提供本地加密存储能力，却没有官方保证其数据一定排除在 uTools 数据同步之外。

## 决定

第一版由插件 `preload` 使用用户自己的 API Key，直接请求用户选择的完整模型接口地址。

- 不建设项目自有的模型中转后端；
- 不内置、共享或远程下发开发者密钥；
- React 页面不能读取 API Key、完整请求头或任意 Node.js、Electron 能力；
- `preload` 只暴露按业务用途命名的请求、取消、存储、复制、粘贴和通知接口；
- API Key 使用 `dbCryptoStorage` 保存，页面保存后只显示掩码和末尾四位；
- 每项服务第一次接收用户文本前，显示规范化后的完整翻译 URL、协议、发送资料和重复调用说明；
- URL 的 origin、路径或查询参数改变后，原确认失效；
- 远程地址只允许 HTTPS，本地回环地址可以使用 HTTP；
- 跨域重定向立即停止，同源重定向最多三次；
- 密钥、源文、译文、术语和参考译例不得进入运行时日志、遥测、错误快照或评测缓存；
- 隐私说明明确告知客户端密钥可能被本机高权限程序或调试手段提取，也可能因用户开启 uTools 数据同步而产生远端或其他设备副本。

## 原因

这一选择能在不维护服务器、账户和计费系统的情况下支持多个服务配置，也让用户决定使用哪项服务、模型和密钥。请求不经过项目运营方的服务器，项目也不因此取得用户文本的中转副本。

代价是无法提供服务端密钥隔离、统一审计、集中撤销、可靠限流和服务端内容策略。直连只减少一个中转方，并不表示文本没有离开设备，也不表示 API Key 在客户端绝对安全。

## 后果

正面影响：

- 第一版部署和运营范围较小；
- 用户可以保存多项渠道并快速切换；
- 项目不承担统一购买和转售模型额度的责任；
- 没有项目自有服务器保存翻译请求或结果。

限制和风险：

- 各服务的可用性、数据保留、费用和限流由用户与该服务之间的关系决定；
- Electron 客户端不能符合“密钥只存在服务端”的安全建议；
- 删除插件本地数据不能保证删除 uTools 已同步的副本，也不能删除模型服务可能保留的数据；
- 自定义兼容服务的协议差异只能在第一版规定的有限字段和事件范围内处理；
- 若未来需要团队密钥、统一账单、集中策略或更强的密钥保护，必须重新评估架构。

## 未采用的方案

### 项目自建中转后端

它可以把供应商密钥保留在服务器，并统一鉴权、限流和协议适配，但会引入账号、部署、监控、成本、数据处理责任和更复杂的隐私合规。第一版个人使用阶段不采用。

### 在插件内放置共享密钥

插件源码和 `preload` 必须可读，共享密钥无法可靠隐藏，还会让泄露、滥用和费用归属失控，因此禁止。

### 只使用 uTools 内置 AI

这种方案不需要用户管理外部密钥，但不能满足用户已确认的 DeepSeek 官方渠道、自定义完整 URL和多服务便捷切换需求，因此不作为第一版唯一渠道。

## 重新评估条件

出现以下任一情况时，应新建 ADR 取代本决定：

- 增加团队账号、共享额度或统一账单；
- 需要项目方托管供应商密钥；
- 需要服务端内容策略、审计、缓存或可靠任务队列；
- 市场审核、法律要求或供应商条款不再允许当前直连方式；
- uTools 提供了具有明确本机隔离和密钥保护保证的新能力。
