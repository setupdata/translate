## 打包前的自动检查

在干净工作区运行：

```bash
npm install
npm test
npm run prepare:upxs
```

`prepare:upxs` 会先执行生产构建、类型检查、剪贴板边界检查、运行时语法检查和发布目录检查，再生成 `artifacts/upxs-input/ruyi-translate-<version>/`。随后必须在 uTools 开发者工具中选择该目录的 `plugin.json`，使用“打包”生成签名 UPXS。不能把 ZIP 文件改名为 `.upxs` 代替该步骤。

测试内容必须使用可检索的合成标记，不得使用真实密钥、个人信息或业务文本。

## 实机用例

### 1. 安装、入口和键盘

安装本次 UPXS，分别验证“如意翻译”“翻译”“fy”“用如意翻译”和“如意翻译设置”入口。确认带入文本保留首尾空白与换行。Windows 和 Linux 验证 `Ctrl+Enter`，macOS 验证 `Command+Enter`；三平台都验证普通 Enter 只换行、Escape 取消、可见按钮可用键盘到达、焦点在打开和关闭对话框时位置清楚。

### 2. HTTPS 和本机回环 HTTP

使用受控 HTTPS 服务验证完整地址确认、鉴权和翻译；使用 `127.0.0.1`、`localhost` 和条件允许时的 `::1` 验证本机 HTTP。另行验证非回环 HTTP 被拒绝、同源重定向不超过三次、跨域重定向在发送密钥和翻译资料前停止。仓库自带模拟服务只覆盖本机 HTTP，不能作为 HTTPS 实测结果。

### 3. 后台、取消和通知

在请求进行中普通隐藏插件，确认进程仍存活时请求尽力继续，60 秒无数据超时和 10 分钟总时限仍有效。记录完成、失败和超时通知是否送达，确认通知正文不含源文、译文、术语、参考译例或密钥；点击通知应返回当前翻译，不得自动复制或粘贴。再验证取消、新文本替换旧任务和正常结束进程，旧任务不得发送通知。系统通知和后台网络不保证必达，平台差异应如实记录。

### 4. 复制与粘贴

点击“复制译文”，确认剪贴板只有纯文本且插件保持可见；点击“粘贴回原窗口”，确认目标窗口收到纯文本。验证确定性严重风险会禁用粘贴，确认风险后只允许复制；确认插件不会自动读取、监听、轮询、复制或粘贴。

### 5. 深浅主题和辅助技术

分别切换系统浅色和深色主题，检查正文、错误、当前状态、风险提示和焦点轮廓的对比度；提示不能只靠颜色表达。使用该平台常用辅助技术验证准备、流式输出、完成、失败和取消状态可识别，流式更新不会反复抢占焦点或逐字朗读。改变窗口高度和窄宽度，确认主要操作仍可见或可滚动到达。

### 6. 进程结束和数据残留

以唯一合成标记完成一次含源文、译文和临时术语的任务，记录插件进程 PID 和测试前的插件可控数据库、文件及日志基线。结束插件进程后启动新进程，确认当前翻译不能恢复。随后在插件可控的 uTools 本地数据库、加密存储、插件文件、运行日志、性能汇总和遥测目录中搜索合成标记，结果应为零。

这里不把模型服务已经保留的请求，或 uTools 已同步到远端和其他设备的副本，计作插件能够保证删除的范围；这些项目应记录为边界说明，而不能写成已删除。
